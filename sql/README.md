# SQL: проверка данных ITSM-системы

[← К оглавлению](../README.md)

Запросы, которыми проверяется целостность данных после UI- и API-тестов: что записи, созданные через интерфейс или API, сохранились в БД корректно. Схема — упрощённая учебная модель ITSM (инциденты, группы, пользователи, SLA), диалект SQLite.

**Файл:** [itsm_checks.sql](itsm_checks.sql) — схема, тестовые данные с заложенными дефектами и 8 запросов.

| № | Проверка | Приёмы | Находит в тестовых данных |
| --- | --- | --- | --- |
| 1 | Инциденты без номера INC | `IS NULL`, `LIKE` | Инцидент, созданный через API без номера |
| 2 | Решённые инциденты без кода решения | `IN`, `OR` | INC0000003 |
| 3 | Приоритет не по матрице «Влияние × Срочность» | Вычисляемое поле | INC0000004 |
| 4 | Исполнитель не из группы инцидента | `JOIN`, `LEFT JOIN` | INC0000004 |
| 5 | Исполнитель без роли агента | `JOIN`, `NOT IN` | — |
| 6 | Инцидент в «Ожидании», а SLA не на паузе | `JOIN` | INC0000004 |
| 7 | Активные инциденты без SLA | `LEFT JOIN … IS NULL` | Инцидент без номера |
| 8 | Сводка по группам и статусам для отчёта | `GROUP BY`, `COUNT`, `COALESCE` | — |

Проверки 1–7 должны возвращать 0 строк: любая строка в результате — дефект данных.

Запуск: открыть файл в DBeaver с подключением SQLite и выполнить скрипт целиком (Alt+X), либо:

```bash
sqlite3 :memory: < itsm_checks.sql
```
