# SimpleOne — ITSM-платформа

[← К оглавлению](README.md)

SimpleOne — российская low-code платформа для управления IT-услугами (ITSM) по практикам ITIL. Пользователи создают обращения через портал самообслуживания, агенты поддержки обрабатывают их в агентском интерфейсе с контролем SLA.

| Параметр | Значение |
| --- | --- |
| Тип продукта | Web-приложение (B2B, SaaS / on-premise) |
| Роль | QA-инженер (ручное тестирование) |
| Модули | Управление инцидентами, запросы на обслуживание, портал самообслуживания, SLA, база знаний, роли и права доступа, REST API |
| Окружение | Windows 11, macOS; Chrome, Firefox, Yandex Browser, Safari |
| Инструменты | Jira, Confluence, TestIT, Postman, Chrome DevTools, DBeaver |

**Задачи на проекте:**

- Анализ требований и пользовательских историй, вопросы аналитикам по несостыковкам.
- Написание и актуализация чек-листов и тест-кейсов в TestIT.
- Функциональное, smoke- и регрессионное тестирование перед релизами.
- Проверка ролевой модели: пользователь портала, агент, руководитель группы, администратор.
- Тестирование REST API в Postman: CRUD-операции над записями, авторизация, валидация ответов.
- Проверка данных в БД через SQL-запросы (SELECT, JOIN).
- Оформление баг-репортов в Jira и проверка исправлений.

## Тест-кейсы

Тест-кейсы покрывают позитивные, негативные и граничные сценарии. Общее окружение: тестовый стенд, Chrome (последняя версия), Windows 11.

### TC-SO-001. Создание инцидента агентом с валидными данными

Приоритет: High · Тип: позитивный · Предусловие: авторизация под агентом группы «1-я линия».

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Открыть «Инциденты» → «Создать» | Открыта форма, статус «Новый», поле «Номер» недоступно для редактирования |
| 2 | Заполнить: Заявитель = «Иванов И.И.», Услуга = «Электронная почта», Тема = «Не отправляются письма» | Поля заполнены, заявитель выбран из справочника |
| 3 | Выбрать Влияние = «Высокое», Срочность = «Высокая» | Приоритет автоматически = «Критичный» |
| 4 | Нажать «Сохранить» | Запись сохранена, присвоен номер формата INC0000000, прикреплён SLA |
| 5 | Открыть список инцидентов | Новая запись в списке с верными значениями полей |

### TC-SO-002. Сохранение инцидента с незаполненным обязательным полем

Приоритет: High · Тип: негативный · Предусловие: авторизация под агентом, открыта форма нового инцидента.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Заполнить все обязательные поля, кроме «Тема» | — |
| 2 | Нажать «Сохранить» | Запись не сохранена, поле «Тема» подсвечено, сообщение «Заполните обязательные поля» |
| 3 | Ввести в «Тема» только пробелы и нажать «Сохранить» | Запись не сохранена, поле считается пустым |

### TC-SO-003. Загрузка вложения: граничные значения размера

Приоритет: Medium · Тип: граничные значения · Предусловие: лимит вложения в настройках стенда = 25 МБ; открыт существующий инцидент.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Прикрепить файл 24,9 МБ | Файл загружен, отображается во вложениях |
| 2 | Прикрепить файл ровно 25 МБ | Файл загружен |
| 3 | Прикрепить файл 25,1 МБ | Файл не загружен, сообщение о превышении лимита |
| 4 | Прикрепить пустой файл 0 Б | Сообщение об ошибке или загрузка по требованиям, без ошибки 500 |

### TC-SO-004. Пауза SLA в статусе «Ожидание»

Приоритет: High · Тип: переходы состояний · Предусловие: инцидент в статусе «В работе» с активным SLA на решение (8 рабочих часов).

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Зафиксировать остаток времени SLA на вкладке SLA | Таймер активен |
| 2 | Перевести инцидент в «Ожидание» с причиной «Ответ пользователя» | Статус SLA = «Приостановлен» |
| 3 | Подождать 10 минут и обновить страницу | Остаток времени не изменился |
| 4 | Вернуть инцидент в «В работе» | SLA возобновлён, отсчёт продолжается с зафиксированного остатка |

### TC-SO-005. Доступ к чужому обращению через подмену ID в URL

Приоритет: Critical · Тип: безопасность / роли · Предусловие: есть пользователи A и B портала, у каждого своё обращение.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Войти на портал как B, скопировать ID своего обращения из URL | — |
| 2 | Выйти, войти как A | Открыт портал пользователя A |
| 3 | Подставить ID обращения B в URL карточки | Отказ в доступе, данные обращения B не отображаются |

### TC-SO-006. API: создание инцидента через REST API

Приоритет: High · Тип: API, позитивный · Предусловие: получен токен сервисной учётной записи, в Postman заданы переменные окружения `{{base_url}}` и `{{token}}`.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Отправить POST на эндпоинт таблицы инцидентов, заголовок `Authorization: Bearer {{token}}`, тело: `{"subject": "API test", "impact": 2, "urgency": 2}` | Код 200/201, в ответе `sys_id` и `number` новой записи |
| 2 | Проверить время ответа и Content-Type | Время < 1 с, `Content-Type: application/json` |
| 3 | Отправить GET по полученному `sys_id` | Код 200, значения полей совпадают с отправленными |
| 4 | Открыть запись в UI | Инцидент отображается, приоритет рассчитан по матрице |

## Баг-репорты

Баг-репорты оформлены по шаблону Jira; при заведении прикладывались скриншоты, видео и HAR-файлы.

### BUG-SO-01. Инцидент переводится в «Решён» без кода решения через кнопку в списке

| Поле | Значение |
| --- | --- |
| Severity / Priority | Major / High |
| Окружение | Тестовый стенд, Chrome 129, Windows 11 |
| Предусловие | Агент авторизован, есть инцидент в статусе «В работе» |
| Шаги | 1. Открыть список «Инциденты». 2. Отметить чекбоксом инцидент. 3. В групповых действиях выбрать «Решить». |
| Фактический результат | Статус меняется на «Решён», поля «Код решения» и «Комментарий решения» пустые |
| Ожидаемый результат | Открывается форма с обязательными полями решения, как при смене статуса из карточки |
| Вложения | Видео воспроизведения, скриншот карточки после действия |

### BUG-SO-02. На портале при ширине экрана 1366 px кнопка «Отправить» перекрывается футером

| Поле | Значение |
| --- | --- |
| Severity / Priority | Minor / Medium |
| Окружение | Тестовый стенд, Firefox 131, Windows 11, 1366×768, масштаб 100% |
| Предусловие | Пользователь портала авторизован |
| Шаги | 1. Открыть каталог услуг. 2. Выбрать услугу с длинной формой (10+ полей). 3. Прокрутить до конца формы. |
| Фактический результат | Кнопка «Отправить» наполовину скрыта зафиксированным футером, клик по верхней части не срабатывает |

| Вложения | Скриншоты Firefox и Chrome для сравнения |

### BUG-SO-03. SLA продолжает отсчёт после перевода инцидента в «Ожидание» через комментарий агента

| Поле | Значение |
| --- | --- |
| Severity / Priority | Critical / Highest |
| Окружение | Тестовый стенд, Chrome 129, Windows 11 |
| Предусловие | Инцидент «В работе» с активным SLA на решение; включено правило «Вопрос заявителю → Ожидание» |
| Шаги | 1. В карточке инцидента отправить комментарий с типом «Вопрос заявителю». 2. Убедиться, что статус стал «Ожидание». 3. Через 15 минут открыть вкладку SLA. |
| Фактический результат | Статус SLA «В процессе», остаток времени уменьшился на 15 минут. При ручной смене статуса пауза работает |
| Ожидаемый результат | SLA приостановлен, остаток времени не меняется |
| Вложения | Скриншоты вкладки SLA до и после, запись истории изменений |
